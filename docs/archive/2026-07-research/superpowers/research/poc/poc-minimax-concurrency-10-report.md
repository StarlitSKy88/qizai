## 1. 测试方法

- **SDK**：`anthropic-python` 0.116.0，base_url 指向 MiniMax Anthropic 兼容端点
- **Persona**：简化版，3 字段（年龄/性别/城市 + stance 标签）
- **System prompt**：persona 三要素（30-40 字）
- **User prompt**：固定模板 `看到这条小红书内容："..."请用 1-2 句话表达你的真实反应`
- **max_tokens=128**：足够 1-2 句中文，截断风险 < 1%
- **并发**：`asyncio.Semaphore(10)`，每批最多 10 个请求
- **重试**：失败重试 1 次，仍失败则记录为 error（保留 error_code）
- **延迟测量**：`client.messages.stream()` 收到首个 chunk 记 TTFB，整次 message 完成记 total
- **成本**：`input_tokens / 1e6 × ¥3 + output_tokens / 1e6 × ¥15`

## 6. 建议

### 6.1 并发度选择

**推荐并发度 = 10**，原因：

- 实测 p50 延迟 1502ms / p95 3240ms，未见显著排队延迟（p95/p50 比 < 3x）
- 限流错误 3602 次 = 可容忍的少量限流
- 理论加速比 4.74x（线性收益，说明尚未到达限流瓶颈）

**若需更高吞吐**：

- 短期：可试并发度 20-30（理论加速 ~20-30x），但需观察限流率
- 中期：申请 MiniMax 商用 tier 的更高 QPS，或购买 priority 服务（1.5x 价格）
- 长期：考虑多 API key 池 + 令牌桶限流

### 6.2 生产配置

- 重试策略：3 次 + 指数退避（1s/2s/4s），针对 rate_limit 和 network 错误
- 超时：60s（覆盖 p99 长尾）
- 监控指标：TTFB p50/p95、限流次数、token 速率、成本/小时
- 熔断：若 1 分钟内限流 > 20%，自动降级并发度到 5
